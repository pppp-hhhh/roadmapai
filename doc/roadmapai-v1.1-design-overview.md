> 范围：仅整理对项目的识别结论与 v1.1 的设计切入建议。后续每个方向展开为"页面级设计稿"时再单独成文。

## 一、项目画像

### 1.1 产品定位

RoadmapAI 是一款基于 **Tauri** 的桌面端 AI 学习路线生成工具，核心形态是"输入主题 → AI 生成结构化学习路径 → 边学边用闪卡 / AI 导师巩固"。

- **运行形态**：桌面应用（Windows / macOS / Linux），前端使用 WebView2 / WKWebView。
- **数据存储**：本地化存储（`src-tauri` 目录 + `libsqlite3-sys` 构建产物暗示使用 SQLite）。
- **AI 接入**：用户自备 API Key，支持 OpenAI、Anthropic、DeepSeek 以及自定义 BaseURL（兼容任何 OpenAI 协议端点）。
- **可选增强**：Tavily 搜索 API，用于在生成路线时检索真实可访问的学习资源。

### 1.2 技术栈

- 前端框架：React 18 + TypeScript + Vite 5
- 路由：React Router 6
- 状态管理：Zustand 5（按 store 拆分：`useRoadmapStore` / `useChatStore` / `useFlashcardStore` / `useSettingsStore`）
- 样式：Tailwind CSS 3（自定义 `primary` 色板），`index.css` 中定义了 `.markdown-content` 排版与滚动条
- Markdown 渲染：react-markdown + remark-gfm + rehype-highlight + lowlight
- 图标：lucide-react
- 后端：Tauri 2（Rust），通过 `invoke()` 暴露命令给前端

### 1.3 信息架构（路由）

| 路由 | 页面 | 主要职责 |
| --- | --- | --- |
| `/` | HomePage | 路线列表 + 进度总览 |
| `/create` | CreateRoadmapPage | 创建学习路线（含分阶段生成进度弹窗） |
| `/roadmap/:id` | RoadmapDetailPage | 时间线式阶段详情 + 任务 + 资源 + 测验 |
| `/flashcards` | FlashcardsPage | SM-2 间隔重复复习 + 新卡片学习 |
| `/tutor` | AiTutorPage | AI 聊天导师（可绑定路线作为上下文） |
| `/settings` | SettingsPage | API Key / 模型 / 主题 / Tavily |

全局壳层：`Layout` 提供 16px 宽的图标侧边栏、`StudyTimer` 浮窗、深浅主题切换。

### 1.4 核心数据模型

- **Roadmap**（路线）：`id` / `title` / `description` / `estimated_total_hours` / `created_at`
- **Stage**（阶段）：`order` / `name` / `objective` / `estimated_hours` / `stageType` ∈ {learning, quiz, project} / `isLocked` / `isFallback` / `tasks[]` / `quiz?` / `passThreshold`
- **Task**（任务）：`title` / `content`（markdown） / `task_type` ∈ {reading, exercise, project, video, quiz} / `code_example?` / `exercise?` / `is_completed` / `resources[]`
- **Resource**（资源）：`title` / `url` / `snippet?` / `resource_type` ∈ {documentation, video, course, article}
- **Flashcard**（闪卡）：`question` / `answer` / `repetitions` / `ease_factor` / `interval` / `next_review_date`
- **ChatMessage**：`role` ∈ {user, assistant} / `content` / `timestamp`
- **ProgressEvent**：生成路线时的四阶段推送事件 `started → outline_complete → stage_started/completed → completed`

### 1.5 v1.0 UI/UX 现状

- **壳层**：16px 宽的"图标 only"侧边栏 + 主内容区 + `StudyTimer` 浮窗。功能入口被压缩成 5 个图标，无文字标签、无层级。
- **色系**：浅/深主题，`primary` 蓝为主色，辅以蓝/紫/绿/橙/黄区分任务类型与功能区，圆角统一 `rounded-xl` / `rounded-2xl`，阴影克制。
- **节奏**：表单居中 `max-w-2xl`、详情页 `max-w-3xl`，整体视觉密度中等偏轻，留白充足。
- **亮点交互**：
  - 创建路线时有四阶段步骤指示器（大纲 / 骨架 / 内容 / 完成），带渐变流动进度条，可中途取消——这是 v1.0 的体验亮点。
  - 路线详情页采用时间线 + 阶段圆点，支持锁定 / 测验 / 降级（fallback）状态可视化。
  - 资源卡片支持悬停编辑/删除，任务可展开查看 markdown + 代码 + 练习 + 资源。
  - 闪卡有 3D 翻牌动画 + 6 级 SM-2 评分（emoji + 颜色编码）。
  - AI 导师支持选择路线附加上下文（自动注入"当前阶段"信息）。

## 二、v1.0 体验痛点

| 区域 | 现状 | 痛点 / 风险 |
| --- | --- | --- |
| 侧边栏 | 16px 仅图标，5 个入口 | 新用户无引导；增加新模块会塞不下；缺少"今天该做什么"等主动提示 |
| 首页 | 卡片网格 + 搜索 + 删除 | 大量路线时无筛选/标签/归档；进度条不够立体；空状态过于简单 |
| 创建页 | 4 字段表单 + 弹窗进度 | 主题/水平/难度三段式抽象，对小白仍有距离；"目标"留空会让 AI 输出不可控 |
| 路线详情 | 时间线 + 大弹窗 | 弹窗嵌套弹窗，宽度受限；编辑资源是内嵌表单易误操作；右侧无总览缩略图 |
| 闪卡 | 翻牌 + 6 档评分 | 桌面端竖屏偏窄；创建卡片只支持手动，没有"从任务/AI 一键转卡" |
| AI 导师 | 标准聊天 | 没有"按当前阶段提问"的快捷入口；没有把回答沉淀为卡片或任务的回路 |
| 设置 | 一长串表单 | 缺首次启动引导；BaseURL 等字段对非技术用户过深 |
| 全局 | 缺乏骨架屏/空状态统一规范 | 加载态都是单一 spinner；空状态文案与样式各页面不统一 |

## 三、v1.1 设计的 6 个切入方向

### 方向 1：侧边栏重做（上下文 + 主动提示）

把 16px 的图标条扩展为可折叠的双层结构：

- 顶部"上下文区"：当前正在学习的路线、当前阶段、今日待办（待复习闪卡数 / 未完成任务数）。
- 中部"主导航"：可显示文字标签，支持折叠态/展开态。
- 底部"全局"：设置、主题、用户。

**价值**：解决 v1.0 的"工具冷启动"问题，把"今天该学什么"从被动查找变为主动推送。

### 方向 2：路线详情页重做（主+侧布局）

放弃"时间线 + 弹窗嵌套弹窗"，改为：

- 左侧固定时间线（可折叠为图标列）。
- 右侧主内容面板：阶段目标、任务列表、资源。
- 资源编辑改用侧拉抽屉 + 实时预览，避免内嵌表单误操作。
- 顶部增加阶段切换器，支持快速跳过到指定阶段。

**价值**：解决 v1.0 弹窗嵌套造成的操作中断和视野受限问题。

### 方向 3：创建页向导化

把当前的 4 字段表单包装为分步对话式向导：

- 步骤 1：主题（含示例与反例，例如"机器学习"好于"AI"）。
- 步骤 2：水平（带描述："我看过几篇博客" → 入门 / "能写简单模型" → 进阶）。
- 步骤 3：目标（改为必填，提供模板：求职面试 / 期末复习 / 个人兴趣 / 项目实战）。
- 步骤 4：偏好（每周可投入时长、难度、是否需要项目）。

每步展示"AI 接下来会做什么"的预期，降低用户对黑盒的焦虑。

**价值**：拉高首条路线的生成质量，减少"AI 输出不符合预期"的挫败感。

### 方向 4：AI 闭环（让已有数据活起来）

v1.0 的数据模型已经预留了"AI 输出 → 路线 / 任务 / 闪卡"的连接，但没有串起来。v1.1 加入：

- 在 AI 导师回答底部加入"转成闪卡" / "转成新任务"按钮。
- 在任务详情页加入"基于此任务向我提问"快捷入口。
- 在闪卡复习中标记"记不住"时，自动向 AI 导师发起"用另一种方式解释"。

**价值**：让"AI 提问 → 沉淀为资产"形成回路，显著提升用户对闪卡与路线的复访率。

### 方向 5：空状态与加载态体系化

抽取统一的四态组件：

- **Empty**（空状态）：插画 + 引导文案 + 主操作按钮。
- **Loading**（加载中）：进度感（如路线生成时的分阶段指示器复用到其他场景）。
- **Skeleton**（骨架屏）：列表 / 卡片 / 表单三种预设。
- **Error**（错误态）：分级展示，提供重试 / 反馈 / 降级操作。

**价值**：让产品在不同数据状态下都保持一致的品质感，减少用户对"卡死"的感知。

### 方向 6：首次启动引导（Onboarding）

新用户首次启动时：

- 步骤 1：欢迎页 + 价值主张。
- 步骤 2：配置 API Key（提供 DeepSeek / GPT-4o / Claude 三个一键预设）。
- 步骤 3：选第一个路线主题（提供几个示例主题一键创建）。
- 步骤 4：进入首页，看到刚创建的路线。

**价值**：解决新用户首日激活率低的根本问题；把"配置 + 创建第一条"打通成一条最短路径。

## 四、推荐组合与优先级

**建议 v1.1 主攻 方向 1 + 方向 3 + 方向 4**，原因：

1. **互相独立，可分批交付**：每个方向都能独立成 PR / 独立灰度。
2. **直接拉动留存指标**：
   - 方向 1（侧边栏）提升日活与次回访。
   - 方向 3（创建页）拉高首条路线的完成率与质量。
   - 方向 4（AI 闭环）让闪卡、路线、导师三块数据互相喂养，提升长期价值。
3. **都基于 v1.0 已有的数据模型**，无需重构后端，只需在前端补齐"沉淀回路"的入口与反馈。

**次要（v1.1.x 后续迭代再考虑）**：方向 2（详情页重做）、方向 5（四态体系）、方向 6（Onboarding）可以作为 v1.2 的候选。

## 五、待澄清的开放问题

在进入具体页面级设计稿之前，建议先与产品/技术对齐以下问题：

1. v1.1 是否仍保持桌面端独占？是否要开始考虑移动端只读视图？
2. 路线数据是否会引入云同步 / 多端？若是，Onboarding（方向 6）需要重新设计登录态。
3. AI 闭环（方向 4）涉及后端持久化（导师回答 → 闪卡 / 任务），是否需要走"待审 → 入库"的两步流程？
4. 视觉系统是延续 v1.0 的色板与圆角风格，还是借 v1.1 做一次品牌升级？
5. 度量 v1.1 成功的核心指标是：首条路线完成率、7 日留存、闪卡日复习率，还是 AI 导师日活？
