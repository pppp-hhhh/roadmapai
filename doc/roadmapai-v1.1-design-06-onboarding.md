# v1.1 设计稿 · 方向 6：首次启动引导（Onboarding）

> 范围：新用户首次启动时引导完成"配置 API Key + 创建第一条路线"的完整流程。
> 关联总览：[roadmapai-v1.1-design-overview.md](./roadmapai-v1.1-design-overview.md)
> 状态：v1.1 候选（次优先），可在 1.1.x 或 1.2 落地。

---

## 一、设计目标

1. **首日激活率提升**：把"配置 + 创建第一条"打通为一条最短路径。
2. **降低 API 配置门槛**：通过 3 个一键预设（DeepSeek / GPT-4o / Claude），让非技术用户也能 30 秒配好。
3. **让"第一条路线"质量更高**：用引导式向导（方向 3 的简化版）让用户输入更具体。
4. **可跳过、可回看**：技术用户能快速跳过，新手能完整走完，每步都可回退。

---

## 二、流程总览

5 步线性流程（不可跳步，但可后退）：

| 步骤 | 标题 | 预计耗时 | 是否可跳过 |
| --- | --- | --- | --- |
| 0 | 欢迎页 | 10 秒 | 否 |
| 1 | 选择 AI 提供方 | 20 秒 | 否 |
| 2 | 填写 API Key | 30 秒 | 否 |
| 3 | 选择学习主题 | 30 秒 | 否 |
| 4 | 选择学习偏好 | 30 秒 | 否 |
| 5 | 生成中 → 跳转首页 | 2-5 分钟 | — |

总耗时：约 2-5 分钟（最后一步是 AI 生成，前 5 步 < 2 分钟）。

## 三、布局架构

### 3.1 整体框架

```
┌──────────────────────────────────────────────────────────┐
│ ●─●─●─●─●─●  第 3 步 / 共 5 步                  [跳过] │
│                                                          │
│                                                          │
│                                                          │
│                  [当前步骤内容区]                        │
│                                                          │
│                                                          │
│                                                          │
│  [← 上一步]                              [继续 →]       │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

- 顶部进度条：6 个圆点，激活态蓝色填充，已完成绿色勾选。
- 右上角"跳过"按钮：仅在步骤 1-4 显示，点击会**警告但不阻止**（因 API Key 是必须的，跳过需在首页重新设置）。
- 底部固定操作栏：左 [上一步]、右 [继续]。
- 内容区居中 `max-w-xl mx-auto`，垂直方向 `min-h-[60vh] flex items-center`。

### 3.2 视觉风格

- 全屏 `bg-gradient-to-br from-primary-50 via-white to-blue-50`（浅色）。
- 深色：`bg-gradient-to-br from-gray-900 via-gray-900 to-primary-900/20`。
- 内容卡片：无卡片包裹，内容直接居中（保持轻盈感）。
- 字号：步骤标题 32px / 副标题 16px / 字段标签 14px。
- 主按钮：`bg-primary-600 text-white rounded-2xl px-8 py-4 text-base font-medium`（比常规大一档，强调"完成里程碑"）。

## 五、状态流转

### 5.1 何时触发 Onboarding

- **首次启动**：`localStorage.getItem('onboarding_completed') !== 'true'` 时。
- **手动触发**：设置页加 [重新运行新手引导] 按钮。
- **恢复出厂后**：清空数据时自动重置。

### 5.2 数据持久化

- 每完成一步立即保存到 store + `localStorage`。
- 中途退出应用，下次启动时回到上次的步骤。
- API Key 保存到 Tauri 安全存储（沿用 v1.0 的 `saveApiKey`），重启后自动填充。

### 5.3 跳过行为

- 步骤 1-4 都有"跳过"按钮（右上角）。
- 跳过会显示警告弹窗：
  > "跳过引导意味着你之后需要在首页手动创建第一条路线，确定跳过吗？"
  - [继续引导] [跳过引导]
- 选择跳过则：标记 `onboarding_completed = true`，跳转首页（空状态）。
- API Key 未配置时，首页顶部会显示横幅提醒。

## 八、可访问性

1. **每步都有 `<h1>` 步骤标题**（屏幕阅读器可识别当前位置）。
2. **进度条**用 `<ol>` + `<li>` 语义化实现，标记 `aria-current="step"`。
3. **API Key 输入框**：`autocomplete="off"`，`type="password"`，切换显示时焦点不丢失。
4. **跳过确认弹窗**：默认焦点在"继续引导"按钮（防误点）。
5. **完成页庆祝动画**：尊重 `prefers-reduced-motion`，开启时改为淡入。

---

## 九、技术实现要点

1. **路由**：
   - 新增 `/onboarding`，不与 `Layout` 嵌套（独立全屏布局）。
   - `App.tsx` 中根据 `onboarding_completed` 决定入口路由：未完成 → `/onboarding`，完成 → `/`。
2. **状态**：新增 `useOnboardingStore`，保存 `currentStep` / `provider` / `apiKey` / `topic` / `preferences` / `completed`。
3. **持久化**：
   - 进度用 `localStorage`（轻量，不涉及敏感数据）。
   - API Key 用 Tauri 的 `secret` 存储（v1.0 已实现）。
4. **跳过警告弹窗**：用 `<ConfirmDialog>` 公共组件，焦点陷阱。
5. **完成态跳转**：用 `setTimeout` + `navigate('/roadmap/:id')`，用户中途可点击"立即查看"取消。
6. **GeoIP 推荐**：调用 `ipapi.co/json` 简单判断国家（无 key），国内推 DeepSeek。

## 十、与 v1.0 的差异

| v1.0 元素 | v1.1 改动 |
| --- | --- |
| 无引导流程 | 5 步 Onboarding |
| 用户自行摸索 API Key | 步骤 1-2 引导配置 |
| 创建页面 4 字段平铺 | 引导版用 2 步（主题+偏好） |
| 完成生成后直接跳详情 | 新增完成态展示页 |
| 无"上次进行到哪" | 退出后下次回到同一步 |
| API 配置入口单一 | 设置页新增 [重新运行引导] |

## 十一、验收标准

1. 首次启动自动进入 `/onboarding`，不显示 Layout。
2. 任意步骤退出后下次启动恢复该步骤。
3. API Key 格式错误时 [继续] 按钮禁用。
4. 测试连接成功后 [继续] 才变蓝。
5. 跳过警告弹窗默认焦点在"继续引导"。
6. 完成页停留 5 秒后自动跳转。
7. 用户点击 [开始第 1 关] 立即跳转，跳过倒计时。
8. 设置页 [重新运行引导] 按钮可清空 `onboarding_completed` 并跳转 `/onboarding`。
